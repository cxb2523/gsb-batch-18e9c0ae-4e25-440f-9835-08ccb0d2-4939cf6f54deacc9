# Step 0 fixtures

Ten React Three Fiber files generated by Claude for the "cinematic interactive 3D hero" coverage spike. They are permanent conformance fixtures: `packages/core/test/step0.conformance.test.ts` runs the parser and writer over every one of them.

| Files | How they were generated |
|---|---|
| `A1`–`A5-guide.tsx` | The prompt below **plus** a draft style guide (literal props, a `name` on every node, motion in wrapper components, `// @prism uniform` annotations, one `Canvas`) |
| `B1`–`B5-noguide.tsx` | The same prompt, no guide |

Prompt (themes: liquid-glass orb with particles; glowing globe with rings and a starfield; Stripe-style gradient mesh waves; iridescent torus knot with mouse parallax; chrome blob that distorts and rotates on scroll):

> You are generating one React Three Fiber component file for a React landing page. Task: give this page a cinematic, interactive 3D hero: *theme*. Requirements: one self-contained TypeScript file named Hero.tsx that uses three, @react-three/fiber and @react-three/drei, exports a default React component, and contains its own `<Canvas>`. Reply with ONLY the complete file contents inside a single code block.

Each run was a fresh Claude process with no project context. The files are unedited model output. They are original generated code with no third-party source, committed under the repository's MIT license.

## What the first run measured (AST only, no runtime)

| | with guide (A) | no guide (B) |
|---|---|---|
| R3F host nodes | 160 | 60 |
| Editable literal nodes | 156 / 160 (97.5%) | 43 / 60 (71.7%) |
| No-op byte-identical | 5 / 5 | 5 / 5 |

The test suite asserts these numbers as **floors** (the parser may only get better) and checks, on every file, that a no-op is byte-identical, that a `setProp` changes exactly one span, and that bumping and restoring every plain `position` / `rotation` / `scale` returns to the original bytes.

The sample is small (5 per arm). Treat it as a regression suite and a first signal, not a statistical claim.
