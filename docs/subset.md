# The Prism subset (v1)

Prismbox edits your source file, so it only edits what it can edit safely. This page is the contract. It describes what `@prismbox/core` does today (`SUBSET_VERSION = 1`).

## Nodes

A **host node** is an R3F element: a lowercase JSX tag that is not a DOM/SVG tag (`mesh`, `group`, `pointLight`, `meshStandardMaterial`, `sphereGeometry`, ...). Coverage is measured over host nodes.

`@react-three/fiber`'s `Canvas` (by import binding, aliases included) and the known drei components are also nodes, but they are not counted in coverage.

Each node has a **status**:

| Status | Meaning |
|---|---|
| `editable` | Not locked, not opaque, no spread, and every prop is a literal. |
| `read-only` | Inside a conditional, has a spread prop, or has at least one non-literal prop. |
| `instance` | Generated by `.map()`. Selectable, never rewritten. |
| `opaque` | `bufferGeometry`, `bufferAttribute`, `instancedBufferAttribute`, `primitive`: contents are not understood. |

A node with one expression prop is `read-only` as a whole for coverage, but you can still edit its **other, literal props**: only the expression prop is refused. Nodes that are *locked* (inside `.map()` or a conditional, spread, opaque) refuse every write.

`ref`, `key` and event handlers (`onClick`, ...) are ignored when judging a node and are never written. "Strict" coverage also requires the node to have none of them.

## Literals

A value is a **literal** if it is:

- a number (including unary `-` / `+`), string, boolean or `null`,
- a template literal with no `${}`,
- an array or object of literals,
- an angle form: `Math.PI`, `±Math.PI / n`, `n * Math.PI`,
- wrapped in `as const`, `satisfies T` or `!` (transparent),
- `new THREE.Color(...)`, `Vector2/3/4`, `Euler` with literal arguments,
- a `THREE.X` member, for the `side` and `blending` props only.

Everything else (identifiers, calls, member access, arithmetic beyond the angle forms, templates with expressions) is an expression and read-only.

## Same-file shader bindings

On `shaderMaterial`, the props `vertexShader`, `fragmentShader` and `uniforms` may be an **identifier that resolves to a literal in the same file**:

```tsx
const vert = /* glsl */ `...`;                         // top-level const
const uniforms = { uIntensity: { value: 0.6 } };       // top-level const

function Orb() {
  const u = useMemo(() => ({ uTime: { value: 0 } }), []);   // empty-deps useMemo
  return <shaderMaterial vertexShader={vert} uniforms={u} />;
}
```

Rules: the binding must be a `const` with an `Identifier` name, found in an enclosing block or at the top level; the value must be a literal, or `useMemo(() => <literal>, [])` with an **empty** dependency array whose callback returns it. A `let`, a destructured or parameter binding, or a shadowing name is not resolved. Imports are not followed.

Edits to such a prop land on the **binding's literal**, not on the JSX attribute, and each resolved prop reports `sharedBy` (how many props read the same binding; editing it changes all of them). `vertexShader` / `fragmentShader` are never rewritten (GLSL source is not editable in v1); `uniforms` values are, through `setUniform`.

### Per-key uniforms

A `uniforms` object with some non-literal values, such as `{ uTex: { value: texture }, uMix: { value: 0.5 } }`, is **not** locked as a whole. The node is read-only for coverage, but each key is classified on its own (`PropInfo.keys`, `node.shader.keys`): literal keys stay editable through `setUniform`, and only the non-literal keys are refused (`OUT_OF_SUBSET`). This works for an inline object and for a same-file `const` or empty-deps `useMemo` binding. An entry that is not a `{ value: ... }` object, a spread, or a computed key is a non-literal key.

### `@prism` annotations

GLSL can describe its own uniforms, so any shader gets sliders without a Prismbox import:

```glsl
// @prism uniform uIntensity float 0..1 =0.6
// @prism uniform uColorA color =#7c5cff
```

Types: `float`, `int`, `bool`, `vec2`, `vec3`, `vec4`, `color`. Annotations are read from GLSL that is a literal or resolves to one. They are ordinary GLSL comments: a shader author may keep or delete them, nothing imports anything for them, and they ship in the shader string like any other comment.

## Known drei components

`Environment`, `Float`, `OrbitControls`, `MeshTransmissionMaterial`, `MeshDistortMaterial`, `Lightformer`, `Stars`, `Sparkles`, `PerspectiveCamera` (table with the editable props in `packages/core/src/drei.ts`). Any other component imported from `@react-three/drei` gets an `UNKNOWN_DREI_COMPONENT` diagnostic and is left alone.

## Imports

A scene file may import from `react`, `three` (and `three/...`), `@react-three/fiber`, `@react-three/drei` and relative files. Anything else is reported as `UNSUPPORTED_IMPORT` (a warning; reading and editing still work in the real-page mode).

## Node ids

A node's id is its `name` prop when that is a **unique string literal**, otherwise its path id: the enclosing component, then tags with sibling indexes, for example `Hero:div>Canvas[0]>group[2]>mesh[1]`. A duplicated name makes every node with it `ambiguous`; writes to an ambiguous node return `AMBIGUOUS_NODE`. Prismbox never inserts a `name` as a side effect of another edit; naming is its own explicit `setProp`.

## Instrumentation

`instrument(source, path)` is the one dev-time transform shared by the real-page plugin, the harness fallback and the Playground. It adds `userData-prism="<path>:<line>:<col>"` (the element's position in the original source) after the last attribute of every R3F host element that has a `.userData` (Object3D, Material, BufferGeometry), and injects `<__PrismOverlay />` into the first `<Canvas>`. It never tags `<color>`, `<fog>`, `<primitive>`, attributes or other attach-only types, is idempotent, source-mapped and deterministic, and its output only ever runs in a dev server or sandbox; your file on disk is never changed by it.

`outline(scene)` returns the source-ordered node tree with an edit state per node: `editable`, `partial` (some literal props) or `read-only`.

## Operations

| Op | What it does |
|---|---|
| `setProp` | Overwrites an existing literal in place, or appends an absent prop after the last attribute in the file's own line, indent, EOL and quote style. Numbers are rounded to 3 decimals. A same-length number array keeps its separators and unchanged elements. |
| `setUniform` | Sets `uniforms.<name>.value` on a `shaderMaterial`, inline or through a same-file binding; `new THREE.Color("#hex")` and `new THREE.VectorN(...)` keep their constructor. |
| `applyOps` | Applies a list of ops in order, all-or-nothing. |

Both ops accept `expected` (the value the caller last saw); a mismatch returns `CONFLICT`. Writing a value the file already holds is a no-op that returns the input untouched.

Every write is checked: the output must equal the input with exactly one contiguous span replaced, must re-parse, and the prop must still be a literal holding the requested value. Otherwise the write is refused (`WRITE_VERIFICATION_FAILED`) and nothing is returned.

Not implemented yet: `unsetProp`, `insertChild`, `removeNode`, `setCamera`, `ensureImport`, undo, preserving `Math.PI / n` when writing angles (angles are written as decimals today).

## Error codes

`PARSE_ERROR`, `NODE_NOT_FOUND`, `AMBIGUOUS_NODE`, `OUT_OF_SUBSET`, `READ_ONLY_NODE`, `READ_ONLY_PROP`, `INVALID_VALUE`, `CONFLICT`, `UNIFORM_NOT_FOUND`, `WRITE_VERIFICATION_FAILED`.

## Not editable in v1

GLSL source (uniforms only), expressions such as `position={[x, y * 2, 0]}`, spread props, anything inside `.map()` or a conditional, hook logic, and the internals of imported models and buffer geometry.
